# 智能相册分析系统 PRD

## 1. 产品目标

系统面向个人旅游照片库，将照片、拍摄元数据和轻量图像特征整理成可筛选、可统计、可回看证据的分析页面。课程版本重点验证完整数据链路和可解释展示，不承担生产级账户、权限和海量存储能力。

## 2. 使用对象与场景

- 演示者：通过在线页面或离线 HTML 讲解数据处理流程和分析结果。
- 查看者：按景点类型、时段和季节筛选照片，核对图表与真实图片是否一致。
- 开发者：使用 Flask 接口接入本地照片库，或使用静态 JSON 完成离线展示。

## 3. 核心需求

### 3.1 数据加载

1. 配置 `VITE_PHOTO_DATA_API_URL` 时优先请求后端。
2. API 失败时回退到 `public/data.json`。
3. 离线构建读取内嵌数据。
4. 合法的空数组展示空状态，不得伪装为 Mock 成功。

### 3.2 筛选与分析

- 景点类型、时段、季节采用“且”逻辑。
- 筛选后同步更新命中数、结论、分布图、散点图和图片池。
- 图表包括景点结构、昼夜结构、季节分布和色彩-纹理散点。

### 3.3 图片证据

- 所有展示卡片使用真实脱敏图片。
- 首批加载 24 张，继续加载时每批增加 24 张。
- 点击图片显示类别、时段、季节、色彩分值和纹理复杂度。

### 3.4 后端能力

- 用户注册、相册创建、图片上传和删除。
- EXIF、GPS、拍摄时间、设备信息和地址关键词解析。
- 相册、用户、平台三级统计。
- `GET /api/photos` 输出前端统一数据契约，`GET /media/...` 提供图片。

## 4. 非功能要求

- 亮色响应式界面，支持 390、768、1440 像素宽度。
- 图片公开副本不得包含 EXIF 或 GPS。
- 写接口必须拒绝路径穿越、非法 JSON、伪图片和超限文件。
- 前端源码、后端源码、离线页面和文档可组成不超过 100MB 的提交包。
- 无后端环境时，单文件 HTML 应能双击打开并完成筛选、图表和图片查看。

## 5. 验收标准

- 76 条数据与 76 张图片一一对应，无重复 ID 和缺失资源。
- API 成功、API 失败回退、空相册和非法字段均有确定行为。
- 上传同名图片不会覆盖已有文件或重复污染元数据。
- 删除照片、相册和用户后三级统计保持一致。
- 前端生产构建、逻辑测试、后端 API 测试、数据校验和离线页面检查全部通过。

## 6. 版本边界

课程版本使用启发式图像特征和规则分类，不声称已经训练深度学习模型。JSON 文件存储适合单机演示；数据库、账户鉴权、异步任务和正式图像识别模型属于后续版本。
